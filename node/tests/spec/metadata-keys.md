# DP-request metadata3 and metadata4 (plan amendment 1)

The four metadata strings of a DP request are `metadata1` = node uuid,
`metadata2` = protocol version (`v3`), `metadata3` = geography and the
validator time statements, `metadata4` = capability list. metadata3 and
metadata4 are lists of `key=value` entries separated by `;`. Readers split
on `;` and take each entry up to its first `=` as the key; an entry without
`=` is a bare flag. Values never contain `;`. Commas are value characters
(the trustedzone list, the geography). Readers take the keys order-free; a
request in which a key of the `cu` family appears twice carries no
trustedzone record, and one in which a key of the `pb` family appears twice
carries no bench record.

The example values below are those of `capability-record.json` and
`bench-record.json`, generated by `spec/make/capability-record.js` and
`spec/make/bench-record.js`; this file is written by
`spec/make/metadata-keys.js` from those fixtures.

## metadata4

```
trustedzones=<a,b>;ipfs=<peer id>;startrow=v1;cugflops=<gflops>;cuv=<cuv>;cuat=<t1>;cusig=<DER hex of the record signature>;cuheap=<SCONE_HEAP>;cuworkers=<n>
```

| key | value | written by |
|---|---|---|
| `trustedzones` | comma-separated trustedzone image names of this network the node runs | agent |
| `ipfs` | the node's Kubo peer id; empty when Kubo did not answer | agent |
| `startrow` | `v1`: the agent adds the `etny-st` started row when it starts an order | agent |
| `cugflops` | the record's gflops, field 4 of the line: the node's attested GFLOPS; one CU is 100 GFLOPS (`250` = 2.5 CU); at most `CU_MAX x 100` = 6,400 | agent, from the record |
| `cuv` | the benchmark version of the record (benchmark.json `cuv`); at least `CU_VERSION_MIN` (4) | agent, from the record |
| `cuat` | `t1` of the record: the unix second the benchmark ended, for the CU_TTL check | agent, from the record |
| `cusig` | the trustedzone's DER hex P-384 signature over the record line, in the statement form of `reserved-prefixes.json` for a v2 line | agent, from the record |
| `cuheap` | the `SCONE_HEAP` of the record's last field (`heap=`) | agent, from the record |
| `cuworkers` | the benchmark worker count of the record's last field (`workers=`) | agent, from the record |

A DP request without `cugflops` is an unattested offer; the PoX records it
at one CU, 100 GFLOPS. The validators pass it over, counting it one CU, only
while its `trustedzones=` list names at least one trustedzone, every name it
lists ends in `-unsafe`, the network admits `-unsafe` trustedzones
(ethernity-cas `Deployment::admits_unsafe`) and, where a PoxMatching judges
the network's offers, the offer's open period declares only templates of
those names (its `tzMask`, spec/matching.md section 16 item 43): an
`-unsafe` trustedzone contacts no CAS, so its node never carries a record,
and an `-unsafe` network bakes the PoX of its CAS twin. A passed-over
offer's enclave memory, storage and EPC are unproven: it is judged on
reason 13 above 100 GFLOPS and on no reason of 10 to 12. Any other offer
without `cugflops` (naming no trustedzone, naming one that can carry a
record, on a network that admits no `-unsafe` trustedzone, or whose period
declares a template of another name) is cancelled with reason 9
(`RecordMissing`, below) where the network's validators vote; where they do
not vote it counts one CU. The `cu` prefix names the trustedzone record's
key family: `cugflops`, `cuv`, `cuat`, `cusig`, `cuheap` and
`cuworkers` here, and the `cuval`, `cun`, `cus`, `cut0`, `cut1`,
`cub0`, `cub1`, `cusig0`, `cusig1` group of metadata3. The agent appends
the six metadata4 `cu*` keys after `startrow=v1` and only when it holds a
record; after a reason-9 cancel on a network it adds no DP request without a
record there, unless the request names only `-unsafe` trustedzones, until
its integration test has produced one. The `pb` keys of the bench record
follow the `cu` keys (below, "The bench record").

Example:

```
trustedzones=ecld-nodenithy-amoy,ecld-pynithy-amoy;ipfs=12D3KooWQYhTNQdmr3ArTeUHRYzFg94BKyTkoWBDWez9kSCVe2Xo;startrow=v1;cugflops=250;cuv=4;cuat=1761724810;cusig=306402300696d5835fffb8b950811294f210626e90d1b18c8b47f97fa64e4ef70e4ecd3334198eb09485b8c9d1ba50a3b829ac2e023054527a77efec630239a424aded6f3124ca98f506428efb797229848c8168d6a56f049bf9b8429ee35a5d32bd1a0c4770;cuheap=256M;cuworkers=4
```

## metadata3

```
<lat,lon>;cuval=<validator address lower-case>;cun=<n0>;cus=<salt>;cut0=<t0>;cut1=<t1>;cub0=<block0>;cub1=<block1>;cusig0=<sig t0>;cusig1=<sig t1> -- the first ;-field is the geography and may be empty, in which case the string starts with ;
```

| position / key | value | written by |
|---|---|---|
| first `;`-field | the geography `<lat,lon>`; may be empty | agent |
| `cuval` | the validator that signed both time statements, lower-case 0x hex | agent, from the record |
| `cun` | n0, the 32-byte run nonce of the record, 0x hex: the opening statement's nonce | agent, from the record |
| `cus` | the 32-byte salt of a v2 record, 0x hex: field 8 of the line, drawn after the run | agent, from the record |
| `cut0` | `t0` of the record | agent, from the record |
| `cut1` | `t1` of the record | agent, from the record |
| `cub0` | the `block` field of the t0 statement, decimal | agent, from line 1 of `capability.time.etny` |
| `cub1` | the `block` field of the t1 statement, decimal | agent, from line 2 of `capability.time.etny` |
| `cusig0` | the validator's 65-byte signature over the t0 statement (nonce n0), 0x hex | agent, from the record |
| `cusig1` | the validator's 65-byte signature over the t1 statement (nonce n1), 0x hex | agent, from the record |

The geography is always the first field, so a reader takes index 0 of the
`;` split as the geography (possibly the empty string) and parses
`key=value` entries from index 1 on. `cub0` and `cub1` are not in the
record line: the agent takes them from the `block` field of the two
`GET /validator/time` answers the trustedzone writes to
`capability.time.etny` in the integration bucket, t0 then t1, one JSON
object per LF-terminated line (plan amendment 17; `capabilityTimeEtny` of
`capability-record.json`), and a wrong value fails only the recovery of
`cusig0` / `cusig1` below. A request without `cus` carries a v1 record
(`capability-record.json` `legacyV1`).

Example:

```
44.4268,26.1025;cuval=0x2a0707de23c2c09d6ff7fadbde34c06cdb0e6278;cun=0xf9324b49b24c8561481ef6b84ec6cbeabd1ccd691e3e55f109d1243ea864e569;cus=0xb6df4b03ac8957c50dc55aa44db55bac8e28268c51ad8f7148650749b5d0b954;cut0=1761724800;cut1=1761724810;cub0=29000000;cub1=29000005;cusig0=0x32dac36e060115ab6b0c8904fe92c8588affd0fec146186f68a61902a2f89d7f20c5392feeb2db341616f71eb82f6309fde0c8f6bdd9cd0237f21e43482551a81c;cusig1=0xfaeb40e95667f04e4e09fe927e6c73b5b32221ee7c69a6e8dab279af950a6fc27fac1d554458a73b32df4db8307345366f8e18a530335fa92d1ea7dc9e75740c1b
```

Example with the geography empty (the string starts with `;`):

## Key names

metadata4: `trustedzones`, `ipfs`, `startrow`, `cugflops`, `cuv`, `cuat`, `cusig`, `cuheap`, `cuworkers`, then the bench record's `pbgflops`, `pbcuv`, `pbsig`, `pbheap`, `pbworkers`, `pbencmem`, `pbstorage`, `pbepc`

metadata3: geography (positional, first field), `cuval`, `cun`, `cus`, `cut0`, `cut1`, `cub0`, `cub1`, `cusig0`, `cusig1`, then the bench record's `pbval`, `pbn`, `pbs`, `pbt0`, `pbt1`, `pbb0`, `pbb1`, `pbsig0`, `pbsig1`

## What the validators rebuild from the DP request

The record line itself is in the node's integration bucket, which the
validators do not read, so every signed field is baked, on chain or in these
keys: the line's fields as listed below, and the two time statements' fields
(`chainId` and `registry` baked, `node` = the request's `dproc`,
`t` = `cut0` / `cut1`, `block` = `cub0` / `cub1`; the opening
statement's `nonce` = `cun`, the closing statement's `nonce` = n1). A
validator rebuilds (`<gflops>` from `cugflops`, the other `cu*`
placeholders from the keys of their names)

```
etny-cu|v2|<baked chainId>:<baked pox>|<dproc lower-case>|<gflops>|<cuv>|<cuval>|<cun>|<cus>|<cut0>|<cut1>|<cusig0>|<cusig1>|heap=<cuheap>;workers=<cuworkers>
```

with n1 = `closeNonce(cun, cus, "<cugflops>|<cuv>|heap=<cuheap>;workers=<cuworkers>")`
= keccak256(abi.encodePacked(bytes("ecld-close-1"), n0, salt,
keccak256(utf8(outcome)))) (`capability-record.json` `closeNonce`), and
checks:

- `cusig` verifies over the statement bytes of that line (`0xFF ||
  "ecld-stmt-1" || 0x00 ||` the line, `reserved-prefixes.json`
  `statementForm`; ECDSA P-384, SHA-256 prehash, DER) under a key of the
  first name of the offer's `trustedzones=` list, and only when that name
  is on the member build's baked list of the network's production-signed
  trustedzone names; any other first name gives no key (reason 1). A suffix
  test is not enough: a self-signed trustedzone can carry a name without the
  `-unsafe` suffix (`ecld-nodenithy-iotex-testnet`). The durable form
  takes only keys the network's validator set provisioned;
- `cusig0` recovers to `cuval` over the statement with `nonce` = `cun`
  and `cusig1` over the one with `nonce` = n1, never `cun`; `cuval` is
  a seated member of the registry; `cut1` is at least `cut0` and `cub1`
  at least `cub0`;
- `cut1 - cut0` is at most `BENCHMARK_MAX_SECONDS`; `cuat` equals `cut1`
  and is within `CU_TTL` of the block timestamp; `cugflops` is at most
  `CU_MAX x 100` (6,400); `cuv` is at least `CU_VERSION_MIN` (4);
- the rate bound: `cugflops` is at most W / (cut1 - cut0 - A) x (1 + T) /
  10^9, W = fullRounds x cuworkers x opsPerRound (50000 x
  workers x 8388608), A 4 s and T
  10 % (placeholders to be calibrated on bare metal,
  OD16); a window at or below A bounds nothing. A failed rate bound is
  reason 4 (`RunTooLong`): the window is too long for the GFLOPS stated.

The trustedzones, the probe and the agent hold the two answers' bodies
(`capability.time.etny`, `probe.time.<g>.etny`) and also refuse a closing
body equal to the opening one; `capability-record.json` `closingChecks`
gives a vector for each check.

A v1 record (a request without `cus`, both statements over `cun`, the line
signed in the plain form) is refused on a network whose pricing names a
PoxMatching: its line is rebuilt as v2 and does not verify (reason 1), and
the agent's disposition for 1 is a new integration test. Any other network
admits it as before (`capability-record.json` `admission`).

A failed check, or a missing record on an offer that is not passed over,
cancels the offer where the network's validators vote, with a reason code:
the `uint8` the validators carry in `voteCancel` and the PoX in
`DPRequestCancelled` (ethernity-cas
`capability.rs` `Reason`; PRICING-DESIGN.md section 9). The reasons are
judged in this order: 1 to 8 on an offer that carries `cugflops` (9 on one
that does not and is not passed over), then 13, then 10 to 12 against the
offer's verified bench record, against 0 without one on a network whose
pricing names a PoxMatching (reason 11 is not judged without one
elsewhere); a passed-over offer is judged on 13 above 100 GFLOPS and on no
reason of 10 to 12:

| code | reason | check |
|---|---|---|
| 1 | `RecordSignatureInvalid` | `cusig` verifies under no key of the offer's first trustedzone name on the baked list of production-signed names |
| 2 | `RecordNodeMismatch` | the rebuilt line's node or PoX differs from the request's |
| 3 | `TimestampNotSeated` | `cusig0` / `cusig1` do not recover to `cuval` over n0 and n1, or `cuval` is not seated, or `cut1` is below `cut0` or `cub1` below `cub0` |
| 4 | `RunTooLong` | `cut1 - cut0` above `BENCHMARK_MAX_SECONDS`, or `cugflops` above the rate bound of the window |
| 5 | `RecordExpired` | `cuat` is not `cut1`, or more than `CU_TTL` from the block timestamp either way |
| 6 | `GflopsAboveMax` | `cugflops` above `CU_MAX x 100` (6,400) |
| 7 | `DeliveredBelowAttested` | the node's window holds `CU_STRIKES` strikes (a probe delivered below 80 % of the attested gflops) |
| 8 | `CuVersionBelowMinimum` | `cuv` below `CU_VERSION_MIN` (4); checked after the `GflopsAboveMax` check |
| 9 | `RecordMissing` | the offer carries no `cugflops` and is not passed over: its `trustedzones=` list names none, names a trustedzone that can carry a record (one without the `-unsafe` suffix), the network admits no `-unsafe` trustedzone, or its open period declares a template of a name the list does not hold |
| 10 | `EnclaveMemoryAboveRecord` | the open period's enclave memory (bits 16-23 of the V2 add's `gflops` argument) above `pbencmem` of a verified bench record, 0 without one |
| 11 | `StorageAboveRecord` | the offer's storage above `pbstorage` of a verified bench record; 0 without one on a network whose pricing names a PoxMatching, not judged without one elsewhere |
| 12 | `EpcAboveRecord` | the offer's EPC units (bits 24-39 of the V2 add's `gflops` argument) times 64 above `pbepc` MiB of a verified bench record, 0 without one (D191) |
| 13 | `GflopsAboveRecord` | the offer's GFLOPS (bits 0-15 of the V2 add's `gflops` argument, on which the PoX prices its orders) above `cugflops` of the verified trustedzone record; on a passed-over offer, above 100 |

`cun`, `cus`, `cuheap` and `cuworkers` carry the four fields of the line
that no other key or chain state holds (the run nonce, the salt and the
`heap=;workers=` field); every other field is baked, the request's
`dproc`, or another key. The line carries no block numbers, so `cub0` and
`cub1` are the only source of the statements' `block` field; they are
unsigned by the trustedzone and enter nothing but the recovery above. The
rebuilt line of the example is `lineFromMetadata.rebuilt` of
`capability-record.json` and equals its `line`.

## The bench record

A node's memory probe of one listed enclave size signs a bench record with
the probe key of that size (`bench-record.json`), tagged `etny-pb`:

```
etny-pb|v1|<chainId>:<pox>|<node lower-case>|<gflops>|<cuv>|<validator lower-case>|<n0 0x+64>|<salt 0x+64>|<t0>|<t1>|<sig t0 0x+130>|<sig t1 0x+130>|heap=<h>;workers=<n>;encmem=<g>;custorage=<s>;epc=<e>
```

Fourteen `|` fields. The readings field is exactly the five entries
`heap`, `workers`, `encmem`, `custorage`, `epc` in this order
(`bench-record.json` `readings`: the grammar, 2
accepted and 18 refused fields); the
trustedzone line's last field stays exactly `heap=;workers=`. The signature
is ECDSA P-384 over SHA-256 of the UTF-8 line, DER, lower-case hex, in the
plain form: the probe key signs no client text, and `etny-pb|` is a
reserved prefix (`reserved-prefixes.json`). The closing statement is over
`closeNonce(n0, salt, "<gflops>|<cuv>|<readings>")`.

The node agent appends the bench record's keys after the `cu` keys of the
same string:

| string | keys in order | form |
|---|---|---|
| metadata4 | `pbgflops`, `pbcuv`, `pbsig`, `pbheap`, `pbworkers`, `pbencmem`, `pbstorage`, `pbepc` | decimals; `pbsig` DER hex without `0x`; `pbheap` as `heap=` |
| metadata3 | `pbval`, `pbn`, `pbs`, `pbt0`, `pbt1`, `pbb0`, `pbb1`, `pbsig0`, `pbsig1` | `pbval` `0x`+40 lower-case; `pbn`, `pbs` `0x`+64; times and blocks decimal (blocks from lines 1 and 2 of `probe.time.<g>.etny`); signatures `0x`+130 |

A request carries a bench record only when all seventeen keys are present
and none is written twice (`bench-record.json` `keySets`); a request with
`encmem=`, `custorage=` or `epc=` and no `pb` keys carries none. A
validator rebuilds

```
etny-pb|v1|<baked chainId>:<baked pox>|<dproc>|<pbgflops>|<pbcuv>|<pbval>|<pbn>|<pbs>|<pbt0>|<pbt1>|<pbsig0>|<pbsig1>|heap=<pbheap>;workers=<pbworkers>;encmem=<pbencmem>;custorage=<pbstorage>;epc=<pbepc>
```

and verifies the record in the order of `bench-record.json`
`benchChecks.order`: the keys; the line (tag, version, fourteen fields,
the readings grammar); `pbsig` under the probe key of size `pbencmem` on
the network, from the non-EDMM measurement, and under no trustedzone key;
the node; `pbsig0` and `pbsig1` recover to a seated `pbval` over n0 =
`pbn` and n1; `pbt1` at least `pbt0` and `pbb1` at least `pbb0`;
`pbt1 - pbt0` at most the window bound of size `pbencmem`; `pbt1` within
`CU_TTL`; the claim leaves a region beside the allowance; the region's rate
W / (pbt1 - pbt0) / 10^9, W the region run's fixed work
(`benchChecks.regionWork`), at least 100 / 1000 of the
`cugflops` of the request's verified trustedzone record and at least the
floor (the line names no instruction set, so the lowest of the floor
table); `pbcuv` at least `CU_VERSION_MIN`. No check reads the line's own
GFLOPS, a figure of the enclave's clock. The share, the floors and the
window bounds are placeholders to be calibrated on bare metal (OD16). A
bench record that fails any check proves nothing: the offer is judged on
reasons 10 to 12 as one without a bench record; there is no reason of its
own. The bench record is tied to its node by `ETNY_NODE_ADDRESS` alone, a
host input, until the platform binding of OD50 is built
(`bench-record.json` `platformBinding`).

An offer states at most `floor(pbepc / 64)` EPC units; the example's
`pbepc` 1024 admits 16.
